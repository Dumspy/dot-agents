Token Estimation

estimateTokens(text: string): number
  └─ Math.ceil(text.length / 3.5)

Categories:
  systemPrompt    = estimateTokens(captured.systemPrompt)
  tools (defs)    = sum of estimateTokens(tool.schema) for each tool
  skills          = sum of estimateTokens(skill.description) for each skill
  contextFiles    = sum of estimateTokens(file.content) for each AGENTS.md
  messages        = walk session entries, sum message content tokens
  tool usage      = walk session entries, sum tool call args + results
  images          = estimate based on image count × average base64 size
  compaction      = estimateTokens(compaction.summary) if present

Validation:
  estimated_total = sum of all categories
  actual_total    = ctx.getContextUsage().tokens (from API)
  Display both: "estimated ≈ 46.8k / actual 47.2k"

File Structure

pi/extensions/context/ ├── index.ts # Entry point: register command + event hooks ├── types.ts # Shared types (CategoryBreakdown, ToolCallInfo, etc.) ├── estimate.ts # Token estimation logic (chars/3.5 + validation) ├── capture.ts # before_agent_start capture + session entry walking ├── overlay.ts # TUI overlay component (SelectList + drill-down) └── format.ts # Formatting helpers (token display, bar charts, etc.)

Implementation Plan

  1. Scaffold extension + register /context command
    Create pi/extensions/context/index.ts with default export, register /context command that shows a placeholder notification. Verify it loads with pi -e ./pi/extensions/context/index.ts.
  2. Capture system prompt breakdown
    Hook before_agent_start, capture event.systemPromptOptions into extension state. Store: selectedTools, toolSnippets, contextFiles, skills, promptGuidelines, the full system prompt string.
  3. Token estimation module
    Implement estimate.ts with estimateTokens(text) using chars / 3.5. Add category estimation functions that take the captured state and return per-category token counts.
  4. Session entry walking for tool usage
    Implement capture.ts functions to walk ctx.sessionManager.getBranch(), identify tool calls (from assistant messages) and tool results, estimate tokens per tool and per call. Group by tool name.
  5. Main overlay (Screen 1)
    Build the overlay component using SelectList + DynamicBorder. Show category breakdown sorted by token count descending, with progress bars. Include model name, context usage (from ctx.getContextUsage()), and estimated vs actual validation line.
  6. Tool usage drill-down (Screen 2)
    When "Tool use & results" is selected, show per-tool breakdown. Each tool shows total tokens and percentage of tool usage category.
  7. Individual calls drill-down (Screen 3)
    When a specific tool is selected from Screen 2, show individual calls with their estimated token cost. Show tool name + truncated arguments as label.
  8. Tool definitions drill-down (Screen 4)
    When "Tool definitions" is selected from Screen 1, show per-tool schema costs. Helps identify which tool schemas are most expensive to keep in context.
  9. Edge cases + polish
    Handle: before first prompt (show "No data yet"), after compaction (show compaction summary as category), images (estimate from count), empty categories (hide). Add color coding, theme integration.
  10. Test + iterate
    Test in real sessions. Compare estimated vs actual totals. Tune the chars/3.5 divisor if consistently off. Add to dot-agents repo for deployment via Nix/Home Manager.
